## 〇、整体链路与拦截优先级

```text
浏览器 / 脚本
   │
   ▼
Nginx:8090（docker-compose 映射宿主 8090 → 容器 80）
   │  ① 可疑 UA ($bad_bot)        → 403
   │  ② limit_req / limit_conn    → 429
   │  ③ 蜜罐 location            → 444（直接断连）
   │  ④ /robots.txt              → 200 + Disallow: /
   │  ⑤ 追加 X-Robots-Tag 等响应头
   ▼
AntiCrawlerFilter（Servlet Filter，@Order = MIN_VALUE+10，先于 Spring Security）
   │  1. 已封禁 IP                → 403 + Retry-After
   │  2. 蜜罐路径                 → 立即封禁 + 403
   │  3. 可疑 / 空 User-Agent     → 记违规 + 403（累计 10 次 → 封禁）
   │  4. 路径级滑动窗口限流       → 429 + Retry-After（累计 10 次 → 封禁）
   ▼
Spring Security（JWT 鉴权）
   ▼
AuthServiceImpl：登录前查锁定、失败计数、成功清计数 → 业务码 1006
```

关键差别：

| 拦截点 | HTTP 状态 | 业务码 | 说明 |
|---|---|---|---|
| Nginx `$bad_bot` | 403 | 无（Nginx 默认页） | 边缘层，不经过后端 |
| Nginx `limit_req` | 429 | 无 | 边缘层，`limit_req_status 429` |
| Filter UA / 封禁 / 蜜罐 | 403 | 1013 | 统一 JSON `Result` |
| Filter 限流 | 429 | 1006 | 带 `Retry-After`、`X-RateLimit-*` |
| 登录失败锁定 | 200 | 1006 | `GlobalExceptionHandler` 返回业务报文 |

### 1. `backend/src/main/java/com/edu/aitutor/security/AntiCrawlerFilter.java`（198 行）

入口过滤器，所有反爬判断的“总闸门”。

| 行号 | 代码段 | 作用 |

| L52–L62 | `shouldNotFilter` | 三种情况直接跳过本过滤器：① 总开关关闭；② `OPTIONS` 预检（不带业务数据，放行避免破坏 CORS）；③ 命中 `whitelistPaths`（健康检查、`/error`、`/robots.txt`、`/favicon.ico`） |

| L100–L118 | **第 4 步：路径级滑动窗口限流** | `matchRule()` 取第一条命中规则；无论放行与否都回写 `X-RateLimit-Limit` / `X-RateLimit-Remaining`；超限时补 `X-RateLimit-Reset`、记 `rate-limit:<规则名>` 违规、返回 429/1006。`Retry-After` 由 `writeError` 按剩余秒数写入 |
| L119–L125 | 异常兜底 | `IOException`（客户端断开等）原样抛出；其它异常（如 Redis 故障）**降级放行**并打 WARN，保证风控故障不拖垮业务 |

| L130–L141 | `matchRule` | 按 `rules` 声明顺序匹配，**先配先生效**（auth > ai > qr > api），保证登录接口走更严的 10 次/分钟 |
| L143–L164 | `isBadUserAgent` | UA 为空且 `block-empty=true` 视为脚本；否则转小写做“包含”匹配关键字表；关键字空值有保护。与 Nginx 的 `$bad_bot` 是**两份独立名单**，改一处不要忘另一处 |
| L166–L176 | `matchesAny` | 白名单、蜜罐共用的 Ant 匹配工具，`null`/空串安全 |
| L178–L186 | `addSecurityHeaders` | 追加 `X-Robots-Tag: noindex, nofollow, noarchive`（禁止收录）、`X-Content-Type-Options: nosniff`（禁 MIME 嗅探）、`Cache-Control: no-store`（防缓存泄露） |
| L188–L197 | `writeError` | 统一错误出口：`Retry-After > 0` 才写该头；设状态码、UTF-8、`application/json`；用 `Result.error(code, msg)` 输出与业务一致的结构，前端/脚本可直接解析 |

### 2. `backend/src/main/java/com/edu/aitutor/security/AntiCrawlerGuard.java`（282 行）

真正干活的风控组件：所有 Redis 读写 + 降级策略都在这里。

| 行号 | 代码段 | 作用 |

| L58–L60 | `RATE_LIMIT_SCRIPT` | 把 Lua 注册成 `DefaultRedisScript`，返回类型 `List`（对应 Lua 的三元数组） |

| L72–L80 | `isBanned` | 查 `ai_tutor:anti:ban:{ip}` 是否存在；异常返回 `false`（降级放行） |
| L82–L89 | `getBanRemainingSeconds` | 读封禁 key 的 TTL 秒数，用作 `Retry-After`；异常/无 TTL 返回 0 |
| L91–L114 | `recordViolation` | `INCR` 违规计数，首次写入时设 TTL = 统计窗口；计数达到 `violationThreshold`（默认 10）就调用 `ban()`，原因带 `count=`；异常只 WARN |
| L116–L135 | `ban` | 写入封禁 key（value=原因，TTL=封禁时长），并 `DEL` 违规计数（避免解封后立刻再封）；打 WARN 留痕 |
| L137–L168 | `checkRateLimit` | 参数兜底（limit/window 至少 1）；拼 key `ai_tutor:anti:rate:{rule}:{ip}`；把 `now`、窗口毫秒、上限、`now:UUID` 作为成员传给 Lua；解析返回值，重试毫秒向上取整为秒；**任何异常都返回 allowed**，即限流失效时放行 |
| L170–L193 | `assertLoginAllowed` | 登录前检查账号锁与 IP 锁，取两者 TTL 的较大值；>0 抛 `BusinessException(TOO_FREQUENT)`，提示“请 N 秒/分钟后再试”。先 `catch (BusinessException) throw` 再 catch 其它异常，避免把业务异常吞掉 |
| L195–L218 | `recordLoginFailure` | 账号维度计数，达到 `maxFailures`（5）→ 锁账号；IP 维度计数，达到 `maxIpFailures`（30，放宽以防 NAT 误伤）→ 锁 IP；日志中账号做掩码 |
| L220–L230 | `clearLoginFailure` | 登录成功后只清账号的失败计数与锁；**IP 锁保留**，防止换账号继续爆破 |
| L234–L241 | `increment` | 通用计数器：首次 `INCR` 返回 1 时补 TTL，避免 key 永久驻留 |
| L243–L248 | `lock` | 写锁定标记，TTL = 锁定时长 |
| L250–L253 | `remainingSeconds` | 读 TTL，统一处理 null/负数 |
| L255–L271 | `toLong` / `humanDuration` / `mask` | Lua 返回值转换、秒转“秒/分钟”文案、账号脱敏 |
| L273–L281 | `RateLimitResult` record | 限流结果三元组：`allowed` / `remaining` / `retryAfterSeconds`，附 `allowed()` 工厂方法 |

### 5. `backend/src/main/java/com/edu/aitutor/util/ClientIpUtil.java`（77 行）

反爬的“身份基准”：限流、封禁、登录锁定全按 IP 记账，IP 取错等于风控失效。

| 行号 | 代码段 | 作用 |
|---|---|---|
| L8–L18 | 类注释 | 说明信任模型：**只有 TCP 对端是内网/回环（如 Docker 里的 Nginx）才信任 `X-Real-IP`/`X-Forwarded-For`**；公网直连只认 `remoteAddr`，防止伪造请求头绕过 IP 限流 |
| L21 | `IP_PATTERN = ^[0-9a-fA-F:.]{3,45}$` | 只接受 IPv4/IPv6 形态的字符集，避免把任意头内容写进 Redis key（key 注入/超长） |
| L26–L51 | `resolve` | 主流程：① `remoteAddr` 非内网/回环 → 直接用 `remoteAddr`（忽略一切请求头）；② 内网来源优先 `X-Real-IP`；③ 否则取 `X-Forwarded-For` 中**第一个合法值**；④ 再退回 `remoteAddr`；⑤ 都非法返回 `"unknown"` |
| L53–L65 | `isPrivateOrLoopback` | 正则预校验 + `InetAddress` 判断 loopback / site-local(10.x、172.16-31.x、192.168.x) / link-local(169.254.x、fe80::)，决定是否信任代理头 |
| L67–L76 | `valid` | 去空白、正则校验，非法返回 `null` |

> 测试：`backend/src/test/java/com/edu/aitutor/util/ClientIpUtilTest.java` 用 5 个用例覆盖“优先 X-Real-IP”“XFF 首个合法值”“回退 remoteAddr”“公网伪造头被忽略”“全非法返回 unknown”。

## 六、触发条件速查

| 你看到的现象 | 最可能命中的代码 | 改哪里 |
|---|---|---|
| 脚本一请求就 403（HTML 页） | Nginx `$bad_bot` | `nginx/nginx.conf` L29–L33 |
| 脚本一请求就 403（JSON code 1013） | `AntiCrawlerFilter` L90–L98 | `AntiCrawlerProperties.UserAgent.blockedKeywords` |
| 请求正常但很快 429（JSON 1006） | Filter L100–L118 + Guard Lua | `rules[].limit/windowSeconds` |
| 请求正常但 429（Nginx 页） | `limit_req` / `limit_conn` | `nginx.conf` L14–L22 与各 `location` |
| 访问某个正常接口突然 403，10 分钟后恢复 | 违规累计触发 `ban` | `ban.violation-threshold/duration-seconds` |
| 登录一直提示“尝试过于频繁” | `assertLoginAllowed` | `login.max-failures/max-ip-failures/lock-seconds` |
| 所有用户共用同一个限流额度 | `X-Real-IP` 未正确透传 | `nginx.conf` 的 `proxy_set_header` 与 `ClientIpUtil` |
| 健康检查没有 `X-RateLimit-*` | 白名单路径 | `whitelistPaths`，属预期行为 |
