# 四人模块分工与验收计划

> 适用项目：大学生辅助学习 AI 数字人系统  
> 整理日期：2026-11-28  
> 代码核对基线：当前工作区提交 `ae090c4`  
> 分配原则：每人负责所分模块的前端、后端、SQL、测试和演示，不再按前后端横向拆人，以适配期末按功能模块考核。  
> 使用方式：将下文“组员 A～D”替换为实际姓名；如有调整，只交换整组职责，不拆散同一条业务闭环。

---

## 1. 当前项目基线

### 1.1 已有基础

- 认证与用户：密码登录、注册、短信登录、模拟扫码、令牌刷新、退出、当前用户和资料修改。
- RBAC：角色、权限树、角色授权、用户列表和用户角色分配。
- 文件：MinIO 预签名上传、上传确认、下载地址和文件列表。
- 私信：1 对 1 会话、WebSocket、MongoDB 消息、已读/送达、离线补拉、媒体消息等。
- 教师与大屏：一键布置随堂练习、教务数据大屏及相关事件推送。
- 数据库脚本、Docker 中间件编排和前端基础框架已经存在。

### 1.2 尚未形成业务闭环的部分

课程、知识库、数字人、AI 会话、完整作业流程、错题本、学习计划、学习统计、成长报告、课堂备考、通知和教师学情等，当前未找到对应业务 Controller。学生端多数入口仍是界面占位。

AI 服务目前只有架构设计，尚无 `ai-service` 实现；不能把接口文档中的规划状态当作完成状态。

### 1.3 当前验证结果

- 前端 `npm run build`：通过，有包体积提示，不影响本次构建。
- 后端 `mvn compile -DskipTests`：通过。
- 后端测试：18 项中 17 项通过；`JwtUtilTest.placeholder_resolvesEnvVarWhenSet_otherwiseDefault` 受本机已设置的 `JWT_SECRET` 影响失败，应由基础模块负责人修正测试环境隔离。
- 当前工作区核对时无未提交修改；`refactor/redis-repository` 比 `origin/dev` 多 1 个提交。四人并行前先将该分支合回 `dev`，再统一从最新 `dev` 拉功能分支。

## 3. 组员 A：课程资源、知识库与学习计划

### 3.1 前端任务

建议页面：

- `/courses`：课程列表、学科/课程类别筛选。
- `/courses/:id`：课程详情、章节树、知识点标签和掌握度展示。
- `/knowledge-bases`：知识库列表、新建、编辑、文档列表。
- 知识库文档上传：申请预签名 URL、直传 MinIO、确认上传、挂载文档、触发入库、查看状态。
- `/study-plans`：计划列表、新建预习计划、计划详情。
- `/plan-tasks/today`：今日任务和完成操作。
- 通知中心：通知列表、未读数、标记已读。

同步补充课程中心路由，解决当前 `RoleConsole.vue` 已跳转 `/courses` 但路由不存在的问题。

### 3.2 后端任务

第一阶段：

- 第 4 章：4.1、4.2、4.4～4.6。
- 第 9 章：9.1～9.5。
- 第 13 章：13.1～13.3。
- 第 17.2 章：知识库创建、列表、详情、更新、删除。
- 第 17.3 章：维护现有文件接口，修复联调问题。
- 第 17.4 章：文档挂载、列表、详情、删除和入库状态管理。
- 配合组员 B 完成 17.6.3～17.6.5 的权限校验与入库回调。

第二阶段：

- 自定义课程导入、AI 复习计划、考前冲刺计划。
- 第 14.5～14.6 节教师知识点批量导入和标签调整。
- 通用字典接口。

### 3.3 数据表职责

`course`、`chapter`、`knowledge_point`、`knowledge_document`、`knowledge_chunk`、`knowledge_base`、`file_record`、`study_plan`、`review_reminder`、`notification`。

表结构变更必须提供增量 SQL，禁止只修改本地数据库。

### 3.4 最低验收闭环

> 选择课程 → 查看章节和知识点 → 创建知识库并上传资料 → 查看入库状态 → 创建学习计划 → 完成今日任务 → 查看并处理通知。

## 4. 组员 B：数字人伴侣与 AI 智能答疑

### 4.1 前端任务

- 数字人首页：形象、欢迎语和当前学习状态展示。
- 数字人设置：形象、音色、语气、语速和动作配置。
- AI 会话：创建、列表、历史消息、结束会话。
- 对话窗口：SSE 流式渲染、停止/失败提示、引用来源、消息反馈。
- 第二阶段再增加 TTS 播放、ASR 语音输入和 OCR 拍照搜题。

不得将静态回答或前端定时逐字输出冒充后端真实流式对话。

### 4.2 Java 后端任务

- 第 5 章：数字人配置读取、更新和欢迎语。
- 第 6 章：6.1、6.3～6.6，负责会话归属、消息历史、反馈和结束会话。
- 第 17.6.1～17.6.3：向 Python 提供会话上下文、消息落库和知识库访问校验。
- 与组员 A 共同完成文档入库触发及回调，但知识库表和文档表仍归组员 A。

### 4.3 Python AI 服务任务

新建 `ai-service`，至少包含：

- 配置管理、JWT 验签、Redis 黑名单检查和内部 Token 校验。
- 第 17.5.1 节 SSE 流式对话。
- DeepSeek 调用、异常兜底、有限重试和用量记录所需数据。
- RAG 检索：Embedding、Qdrant 过滤检索、引用来源。
- 文档解析、切片、向量入库及 Java 回调。
- Python 不直接连接业务 MySQL；需要业务数据时调用 Java `/internal` 接口。

统一采用第 17.5.1 节的新流式路径，不再单独实现第 6.2 节旧流式链路。

### 4.4 最低验收闭环

> 创建会话 → 挂载已有知识库 → 发送文字问题 → SSE 返回真实模型回答 → 展示引用资料 → 消息成功落库 → 刷新后仍可查看历史 → 点赞/点踩。

第二阶段：数字人语音、拍照搜题、配额控制和更完整的异常恢复。

## 7. 跨模块契约与依赖

| 提供方 | 使用方 | 必须提供的能力 | 禁止事项 |
| --- | --- | --- | --- |
| 组员 A | B、C、D | 课程/章节/知识点查询、知识库访问校验、文件上传下载、计划任务统计 | 使用方不得直接修改 A 的表或 Mapper |
| 组员 B | A、C、D | AI 流式对话、文档入库协同、AI 出题调用契约、对话统计数据 | C 不得另写一套大模型客户端 |
| 组员 C | D | 作业完成、答题、正确率、错题和成绩统计 | D 不得反向修改作业和答题记录 |
| 组员 D | 全员 | 登录身份、角色权限、通用安全能力和大屏事件规范 | 不得绕过 RBAC 自行判断角色 |

具体约定：

1. 跨模块只调用对方 Service 接口或约定事件，禁止跨包直接调用 Mapper。
2. 接口入参、返回字段、错误码变更时，先更新接口文档并通知使用方，再修改代码。
3. ID 在 JSON 中按字符串处理，避免 JavaScript 大整数精度丢失；如现有实现暂未统一，列入联调整改。
4. 新旧接口口径：知识库上传采用 17.3～17.4；AI 流式对话采用 17.5.1；不重复实现旧链路。
5. 公共响应、请求拦截、异常处理和安全配置不得被单个业务组随意改写。

## 9. 期末统一验收标准

每位组员必须独立交付：

1. 至少一条完整可操作的业务闭环，不能只有静态页面或接口定义。
2. 前端真实请求后端，不使用写死数据冒充完成。
3. 本模块的 Controller、Service、Mapper、DTO/VO、前端 API 和页面齐全。
4. 可重复执行的增量 SQL、初始化演示数据和必要配置说明。
5. 正常流程、参数异常、未登录/越权三类基本验证。
6. 更新接口文档状态；只有源码存在才可标 ✅，完成运行期联调后另行记录验收结果。
7. 一份 3～5 分钟模块演示脚本，说明业务价值、前后端调用链路和本人完成内容。
8. 合入后不得导致其他模块无法启动；出现问题由模块负责人优先修复。

### 建议集成顺序

1. 组员 D 先保证认证、权限和测试基线稳定。
2. 组员 A 提供课程、知识点、知识库和文件基础能力。
3. 组员 B、C 并行开发 AI 答疑和作业闭环。
4. 组员 D 接入 A/B/C 的学习数据，完成统计、报告和教师预警。
5. 四人统一联调，最后再开发第二阶段扩展功能。
